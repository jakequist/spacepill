Documentation

Everything SpacePill does, and what it needs from macOS

SpacePill is a menu bar app for navigating macOS Spaces: a colour-coded pill for the Space you're on, hotkeys to relabel it, jump to another one, and take notes. It is a single native executable with no third-party dependencies.

Read first Quick Switch does nothing until you enable macOS's Desktop shortcuts

They are disabled on every fresh macOS install and SpacePill cannot enable them for you. Jump to the setup steps ↓

Requirements #

Operating systemmacOS 13 Ventura or later
ArchitectureApple silicon and Intel
PermissionsAccessibility (required for switching), Input Monitoring (optional, for responsiveness)
System configuration“Switch to Desktop N” shortcuts enabled — see below
Disk footprintThe app, plus plain text files under ~/.spacepill/
NetworkNone. SpacePill contains no networking code.

Installation #

Homebrew

Terminal
brew tap jakequist/spacepill https://github.com/jakequist/spacepill
brew install spacepill

The cask installs SpacePill.app into /Applications. Update it later with:

Terminal
brew update && brew upgrade --cask spacepill

Direct download

Download SpacePill.dmg from the releases page, open it, and drag SpacePill into Applications. Release builds are signed and notarised, so Gatekeeper opens them without a right-click dance.

Build from source

Terminal
git clone https://github.com/jakequist/spacepill.git
cd spacepill

./bin/start.sh            # build + bundle + run
./bin/start.sh -d         # same, detached
./bin/start.sh --debug    # debug config, much faster compiles

Note Always run from a bundle

swift build alone produces a bare executable with no bundle identifier. That silently disables Launch at Login and gives the process a different permissions identity than the shipped app, so grants you make while testing do not apply to the real one. bin/start.sh assembles and signs a proper .app for exactly this reason.

First launch

SpacePill has no Dock icon and no main window — it is a menu bar item only. On first launch it asks for Accessibility permission. If the pill shows ?, switch Spaces once so it can read the current one. Only one instance runs at a time; a second launch detects the first and exits.

Required setup: the “Switch to Desktop” shortcuts #

Critical macOS ships these shortcuts disabled. Quick Switch cannot work without them.

macOS exposes no public or private API for activating a Space. The only way any app can move you to a Desktop is to press the keys you would press yourself, so SpacePill replays your own Switch to Desktop N shortcut. On a stock Mac, none of those shortcuts are bound to anything — which means a brand-new install of SpacePill cannot change Spaces at all, no matter which permissions you have granted.

Fix it once:

  1. Open System Settings → Keyboard
  2. Click Keyboard Shortcuts…
  3. Select Mission Control in the sidebar
  4. Expand Mission Control in the list if it is collapsed
  5. Tick the checkbox for Switch to Desktop 1, Switch to Desktop 2, … — one for every Desktop you want to jump to
  6. Click Done, then reopen the Quick Switch Bar

SpacePill re-reads this configuration every time you open Quick Switch or Preferences, so the change takes effect immediately — no relaunch needed. Preferences also shows a warning box while no shortcut is enabled, with a button that opens the right settings pane.

The default binding is ⌃ plus the Desktop number (⌃ 1, ⌃ 2, …), but you may bind anything you like. SpacePill reads whatever you actually configured and replays that, so rebinding is safe.

Spaces 11 and beyond can never be reached

macOS only defines ten of these shortcuts — internally they are symbolic hotkey IDs 118 through 127, meaning “Switch to Desktop 1” through “Switch to Desktop 10”. There is no eleventh. If you have more than ten Spaces, the ones past the tenth have no shortcut to replay and are therefore unreachable by any app, SpacePill included.

Rather than pretending, Quick Switch greys those rows out, marks them with a “no entry” symbol and explains why in the footer hint. Pressing ⏎ on one does nothing instead of posting a keystroke that would land you somewhere arbitrary.

Why not step there?

Walking to Desktop 12 with repeated ⌃→ presses was tried and removed. Each native transition takes about half a second and swallows arrow keys posted while it is in flight, so multi-step hops reliably landed on the wrong Space. Refusing is more useful than guessing.

Checking what macOS thinks is enabled

The bindings live in the com.apple.symbolichotkeys preference domain. To inspect Desktop 1 (ID 118):

Terminal
# 118..127 = "Switch to Desktop 1..10"
/usr/libexec/PlistBuddy -c "Print :AppleSymbolicHotKeys:118" \
    ~/Library/Preferences/com.apple.symbolichotkeys.plist

An absent entry means the factory default, which for these IDs is off. Note that writing this domain with defaults write does not take effect until the WindowServer re-reads it at login — enable the shortcuts through the System Settings UI, which registers them live.

Permissions #

SpacePill asks for two grants, both under System Settings → Privacy & Security. They do different jobs and failing to grant them fails differently.

Permission What it is for Without it
Accessibility Posting the synthetic keystrokes that change Spaces. Switching has no API, so SpacePill sends the same key presses you would make yourself. Quick Switch cannot change Spaces. The bar still opens and lists your Spaces; pressing ⏎ just does nothing.
Input Monitoring A keyboard event tap that notices ⌃← / ⌃→ presses so the pill can update at the start of the native transition animation instead of after it. Everything still works. The pill simply lags roughly a second behind arrow-key Space switches instead of moving instantly.

Input Monitoring is the scarier-sounding of the two and it is genuinely optional: it exists only to make the indicator feel immediate. If you would rather not grant it, don't — SpacePill also polls and listens for the system's active-space notification, so the pill stays correct either way.

Heads up Updating can reset your grants

macOS keys these permissions to an app's code signature. A rebuilt or re-signed binary can look like a brand-new app and lose both grants, with the symptom that hotkeys and pill tracking silently stop working. Toggling the checkboxes off and on in System Settings often does not rebind them; clearing and re-granting does:

Terminal
tccutil reset Accessibility com.jake.SpacePill
tccutil reset ListenEvent   com.jake.SpacePill

SpacePill also uses private SkyLight/CoreGraphics APIs to read Space IDs and detect transitions. That is a read-only observation of your window server state; nothing is transmitted anywhere.

Open Preferences by right-clicking the pill and choosing Preferences…

Their global hotkeys are not registered until you tick Enable Quick Switch Bar and Enable Space Notes. If ⌘ ⇧ J or ⌘ ⇧ N appears to do nothing on a fresh install, this is why. Quick Edit is always on.

Rebinding

In Preferences, click a hotkey field and press the combination you want. SpacePill registers global hotkeys through Carbon, so a combination already claimed by macOS or another app will not register — if a new binding does nothing, try a different one. Bindings are stored in ~/.spacepill/settings.json.

The menu bar pill #

The pill is a fixed-width capsule showing two things: a circular badge with the Space's 1-based index across all displays, and the Space's label in uppercase. Its fill is the colour you assigned; the badge is a darker shade of it.

A Space you have never configured shows a neutral translucent pill with just the number. If SpacePill cannot determine the current Space at all, the pill shows ? — switch Spaces once and it will pick it up.

Detection combines three sources: the system's active-space notification, a two-second poll, and (with Input Monitoring granted) a keyboard event tap that makes an optimistic guess the moment you press ⌃←/⌃→, so the pill turns over at the start of the animation rather than at the end. If the guess turns out wrong, it reverts within a couple of seconds.

Note that the index is positional: it renumbers whenever Spaces are added, removed or reordered in Mission Control. Labels and colours are keyed by the Space's stable UUID instead, so they follow the Space rather than the slot.

Quick Edit — label and colour a Space #

Press ⌘ ⇧ S (or left-click the pill) to open a small popover for the Space you are currently on.

  • Label — free text, shown uppercased in the pill and searchable from Quick Switch.
  • Colour — seven presets (blue, red, green, orange, purple, pink, grey) plus the system colour picker for anything else.
  • Save (⏎) writes the label and colour against this Space's UUID.
  • Clear (⌫) removes the configuration, returning the pill to its neutral state.

When you open Quick Edit on an unconfigured Space, SpacePill pre-selects the first preset colour that no other Space is using, so a run of new Spaces ends up visually distinct without you choosing anything.

Quick Switch — jump to a Space by name #

Press ⌘ ⇧ J to open a search bar listing every Space across every display, each with its number badge and colour.

  • Type part of a label to filter case-insensitively.
  • Type an exact number to match that Space's index.
  • ↑ ↓ to move, ⏎ to switch, esc to dismiss.

Greyed-out rows

Before showing the list, SpacePill re-reads your System Settings shortcut configuration and works out which Spaces it can actually reach. Rows it cannot reach are dimmed, marked with a “no entry” symbol, and refuse to activate. The footer explains the specific reason for whichever row is selected:

ReasonFix
“Enable Switch to Desktop N in Keyboard Shortcuts to jump here” Tick that Desktop's checkbox — see Required setup.
“Can't jump here — macOS has no shortcut past Desktop 10” Nothing to fix; macOS defines no such shortcut. Reduce your Space count or reorder so the ones you jump to sit in the first ten.

This deliberately fails loudly. A jump that silently does nothing is indistinguishable from a bug, so SpacePill would rather tell you it is refusing.

Space Notes #

Press ⌘ ⇧ N to open a floating scratchpad anchored under the pill. Each Space has its own note, and the panel swaps content the instant you change Space.

  • Markdown highlighting for headings, bold, italics, inline code, fenced code blocks, and list markers.
  • Auto-continued lists: press ⏎ on a -, *, + or numbered list item and the next line starts with the same marker at the same indent.
  • Saves as you type — there is no save button and no unsaved state.
  • Remembers scroll position per Space, so returning puts you back where you were.
  • Auto-sizing panel that grows with the content up to the Max Notes Height you set in Preferences.
  • Per-Space open state: if you leave the panel open on a Space, it reappears when you come back and stays hidden on Spaces where you closed it.
  • The border can take the Space's colour, which makes it obvious at a glance whose notes you're looking at.

Notes are plain Markdown files on disk:

Path
~/.spacepill/space_<index>/notes.md

Caveat Notes are keyed by index, not by Space identity

Labels and colours follow a Space's stable UUID, but note files are named after the Space's positional index. Adding, removing or reordering Spaces renumbers those positions, so existing notes can end up attached to the wrong Space. The files are ordinary Markdown — if this happens, rename the space_<index> directories to match.

The spacepill command line tool #

In development

The CLI is being built alongside the app and its exact flags are still moving. This section describes capabilities deliberately, not a frozen interface. Treat spacepill help on your machine as the authoritative reference.

spacepill is a companion command line tool that lets scripts and other programs do from a terminal what the hotkeys do from the keyboard. That makes Spaces addressable from shell scripts, editor tasks, and the coding agents SpacePill was written for in the first place.

What it can do

Deliberately described at the level of capabilities rather than exact flags — run spacepill help for the precise syntax your build accepts.

Inspect Spaces
Report the Space you are currently on, and list every Space with its number, label and colour — with machine-readable output available for scripting.
Jump to a Space
Switch to a Space by number or by label. Subject to exactly the same constraints as the in-app Quick Switch: the corresponding “Switch to Desktop N” shortcut must be enabled, and Desktops past the tenth cannot be reached. See Required setup.
Label and colour a Space
Set or clear a Space's label and colour from a script — the same thing Quick Edit does, without touching the keyboard.
Read and write Space Notes
Print a Space's notes, replace them from standard input, open them in your $EDITOR, or just print the path to the file. Handy for letting a build script or an agent leave a status line in the scratchpad of the Space it is working in.
Diagnose the setup
spacepill doctor checks whether the app is running, whether the permissions have been granted, and — the usual culprit — which “Switch to Desktop N” shortcuts are actually enabled. Run this first when switching does not work.
Update and report its version
Check for and install a newer SpacePill, or just print the version you have.
Put itself on your PATH
The CLI ships inside the app bundle and can install a symlink for itself into a standard location, so spacepill works from any shell.
Terminal
# The authoritative reference for your installed version:
spacepill help

# Check why switching isn't working:
spacepill doctor

Commands exit non-zero on failure, with distinct codes for “SpacePill isn't running”, “that Space can't be switched to” and “no such Space”, so scripts can tell the cases apart — spacepill help lists them. If spacepill is not found on your PATH, the CLI may not be in the version you have installed yet; check the release notes.

The settings file #

Everything SpacePill persists lives in one directory:

~/.spacepill/
~/.spacepill/settings.json          # hotkeys, toggles, per-space label + colour
~/.spacepill/space_1/notes.md       # notes for the Space at index 1
~/.spacepill/space_2/notes.md
~/.spacepill/space_<N>/notes.md

settings.json is written by the app whenever anything changes. You can read it freely; if you edit it by hand, quit SpacePill first, or your changes will be overwritten on the next save.

~/.spacepill/settings.json
{
  "isQuickSwitchEnabled": true,
  "isNotesEnabled": true,
  "matchSpaceColorForNotesBorder": true,
  "maxNotesHeight": 300,
  "quickEditHotKey":   { "keyCode": 1,  "modifiers": 768 },
  "quickSwitchHotKey": { "keyCode": 38, "modifiers": 768 },
  "notesHotKey":       { "keyCode": 45, "modifiers": 768 },
  "spaceConfigs": {
    "1A2B3C4D-5E6F-7081-9A0B-C1D2E3F40506": {
      "label": "Agents",
      "hexColor": "FF007AFF",
      "isNotesOpen": true,
      "scrollPosition": 0
    }
  }
}

Fields

isQuickSwitchEnabled — bool, default false
Whether the Quick Switch Bar and its hotkey are active.
isNotesEnabled — bool, default false
Whether Space Notes and its hotkey are active.
matchSpaceColorForNotesBorder — bool, default true
Draw the notes panel border in the current Space's colour rather than a neutral hairline.
maxNotesHeight — number, default 300
Maximum height of the notes panel in points. The Preferences slider ranges from 100 to 800 in steps of 50.
quickEditHotKey / quickSwitchHotKey / notesHotKey
Each is { "keyCode": <virtual key code>, "modifiers": <Carbon modifier mask> }. The masks are 256 Command, 512 Shift, 2048 Option, 4096 Control, summed together — so 768 is Command + Shift. Key codes are the usual macOS virtual key codes: 1 = S, 38 = J, 45 = N. Recording a hotkey in Preferences is much easier than editing this by hand.
spaceConfigs
A map from a Space's UUID to its configuration. Keying by UUID is what makes labels and colours survive reordering Spaces in Mission Control.
spaceConfigs[uuid].label — string, optional
The name shown in the pill (uppercased) and matched by Quick Switch.
spaceConfigs[uuid].hexColor — string, optional
Written as 8 hex digits in AARRGGBB order — FF007AFF is opaque system blue. Plain RGB and RRGGBB values are also accepted when reading.
spaceConfigs[uuid].isNotesOpen — bool, optional
Whether the notes panel should reappear when you return to this Space.
spaceConfigs[uuid].scrollPosition — number, optional
Saved vertical scroll offset of the notes panel for this Space.

Deleting settings.json and relaunching resets SpacePill to defaults — which also turns Quick Switch and Space Notes back off. Notes files are not touched by that.

Troubleshooting #

Quick Switch opens but pressing Return doesn't move me

This is almost always one of three things, in order of likelihood:

  1. The “Switch to Desktop N” shortcuts are not enabled. They are off on every fresh macOS install. Enable them → If the row you selected is greyed out, this is definitely it.
  2. Accessibility permission is missing. Check System Settings → Privacy & Security → Accessibility and make sure SpacePill is listed and ticked.
  3. The target Space is past Desktop 10. macOS defines no shortcut for it, so it can never be jumped to.

Some Spaces are greyed out in the list

Deliberate. Either that Desktop has no shortcut enabled, or it sits past Desktop 10. Select the row and read the footer hint — it names the specific reason.

⌘ ⇧ J or ⌘ ⇧ N does nothing

Those hotkeys are not registered until the corresponding feature is switched on. Right-click the pill → Preferences → tick Enable Quick Switch Bar and/or Enable Space Notes.

If a feature is enabled and the hotkey still does nothing, the combination may be claimed by macOS or another app — global hotkey registration fails when something else already owns the combination. Record a different one in Preferences.

Hotkeys worked, then stopped after an update

Permissions are bound to the app's code signature, and a new build can read as a new app. Reset and re-grant:

Terminal
tccutil reset Accessibility com.jake.SpacePill
tccutil reset ListenEvent   com.jake.SpacePill

Then relaunch SpacePill and approve the prompts.

The pill shows ?

SpacePill has not identified the current Space yet. Switch Spaces once. If it stays as ?, the private APIs it reads may have changed in your macOS version — please open an issue with your macOS version.

The pill lags about a second behind ⌃←/⌃→

The keyboard event tap could not be created, which normally means Input Monitoring has not been granted. Everything still works — the pill just updates after the transition instead of during it. Grant Input Monitoring to get the snappy behaviour back. In the log you will see:

Log
[com.jake.SpacePill:spaces] Failed to create space switch event tap

My notes turned up on the wrong Space

Note files are named by positional index, so adding, deleting or reordering Spaces can shift them. Quit SpacePill and rename the ~/.spacepill/space_<index> directories to match the new numbering. See Space Notes.

Launch at Login doesn't stick

Login items require a properly bundled app. This works with the released SpacePill.app; it will not work if you are running a bare swift build binary. Use ./bin/start.sh, which builds a real bundle.

Reading the log

SpacePill logs to the unified system log under its bundle identifier:

Terminal
# live
log stream --predicate 'subsystem == "com.jake.SpacePill"'

# the last five minutes
log show --predicate 'subsystem == "com.jake.SpacePill"' --last 5m

Categories are app, spaces, hotkeys, ui, settings and notes. Space labels and note text are deliberately redacted as <private>. From a source checkout, ./bin/logs.sh wraps these commands.

Starting over

Quit SpacePill, delete ~/.spacepill/settings.json and relaunch. That restores every default, including turning Quick Switch and Space Notes back off.

Uninstall #

If you installed with Homebrew

Terminal
brew uninstall --cask spacepill

# also remove settings and notes:
brew uninstall --zap --cask spacepill

--zap additionally trashes ~/.spacepill and the legacy ~/Library/Preferences/com.jake.SpacePill.plist.

If you installed the app manually

Terminal
# 1. Quit SpacePill from the pill's right-click menu, then:
rm -rf /Applications/SpacePill.app

# 2. Settings and notes (this deletes your notes — back them up first):
rm -rf ~/.spacepill

# 3. Legacy preferences, if you used an early version:
rm -f ~/Library/Preferences/com.jake.SpacePill.plist

# 4. Revoke the permission grants:
tccutil reset Accessibility com.jake.SpacePill
tccutil reset ListenEvent   com.jake.SpacePill

If you enabled Launch at Login, removing the app clears the login item; you can confirm under System Settings → General → Login Items & Extensions.

The “Switch to Desktop” shortcuts you enabled are a macOS setting, not a SpacePill one. They stay on unless you untick them yourself — which is usually what you want.
